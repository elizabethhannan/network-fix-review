    Every agent on this page, where it runs, what it does and whether it is running right now. No agent can change the network on its own; a person approves every change.
    
    
    
      
    Agents
    
      
    
        
    Review: Network telemetry → 1 Diagnosis → 2 Change-safety → Operator decides
    
        
    Audit, on each element: Operator presses Audit → 1 Audit lead plans → 2 Reachability → 3 Performance, Radio or Path → 4 Config → 5 Security → 6 Audit lead writes verdict → Operator: open fix or correct
    
        
    Security, all the time: 1 Fraud, Bot defense, Malware, Intrusion, Identity and MFA → 2 Warning agent ranks, merges, escalates → Operator acknowledges; step-up MFA for high-risk actions
    
        
    Each agent hands its result back to the one that assigned it. Only checks that apply to an element run, so a switch skips Radio and Path. An audit fix opens in Review, where the Diagnosis and Change-safety agents take over.
    
      
    
      
    
    
    
    
    
      
    Definitions
    
      
    
        
    
          
    TermMeaning
    
          
            
    ElementOne part of the network chain, such as a switch group, a WAN link or a service.
    
            
    CheckOne test an agent runs on an element, such as reachability, memory trend or firmware against advisories.
    
            
    VerdictThe audit's likely conclusion for an element: Healthy, Watch, Not up to par or Can't verify.
    
            
    WatchWorking now but trending toward a problem.
    
            
    Not up to parA check failed and the element is likely hurting users or will soon.
    
            
    Can't verifyThe agent lacks the data to judge, so it says so instead of guessing.
    
            
    ConfidenceHow sure the agent is, from 0 to 100%. A verdict is likely, not certain.
    
            
    Hand-offOne agent passes its proposal to another agent to check independently.
    
            
    Hand-backThe agent returns the decision to the operator, who approves, edits or rejects it.
    
            
    CorrectionAn operator marks a verdict or fix as wrong; it becomes a training example.
    
              
        
    
      
    
    
    
  
    

  
    
    
    
    
    
      
    Security agents, always on
    
      
    These agents run all the time, not only during an audit. Each one hands what it finds to the Warning agent. Every high-risk action asks the operator for step-up MFA first.
    
      
    
    
    
    
    
      
    
      
    
    
    
    
    
  
    

  
    
    
    The telemetry is designed backwards from what operators are trying to do. Each goal gets a measure, and each measure tells the model team something specific.
    
    
    
      
    From operator goals to model requirements
    
      
    
        
    
          
    Operator goalWhat we measureWhat it tells the model team
    
          
            
    Fix the problem fast without breaking usersrec_opened → decision time; rollback within 24 hWhich fix types need clearer evidence, and which fixes break things after they are applied
    
            
    Trust the AI only as much as it deservesaccept, edit and reject share by confidence band; rollback by bandWhether the stated confidence is calibrated, band by band
    
            
    Fix it my way when the AI is closedecision_edited {field, from, to}Which parameters the model gets wrong; labeled pairs for fine-tuning
    
            
    Know when the AI does not knowabstain_shown; more_data_requested; diagnosis after more dataWhether abstaining saves bad actions, and which signals are missing
    
            
    Not see a rejected idea again next weekdecision_rejected {reason}; repeat of a rejected fix within 7 daysSuppression rules and negative training examples
    
            
    See that the fix workedoutcome_verified {metric, before, after}Ground truth for the model's predicted impact
    
              
        
    
      
    
    
    
    
    
      
    Event schema
    
      
    
        
    
          
    EventFieldsFires when
    
          
            
    rec_openedrec_id, kind, confidence, riskAn operator opens a recommendation
    
            
    evidence_viewedrec_id, evidence_id, dwell_msAn operator hovers or focuses an evidence chart
    
            
    decision_acceptedrec_id, confidence, ms_to_decideThe fix is applied as proposed
    
            
    decision_editedrec_id, field, from, to, ms_to_decideThe operator changes the fix, then applies it
    
            
    decision_rejectedrec_id, reason, note, ms_to_decideThe operator turns the fix down
    
            
    more_data_requestedrec_id, probe, durationThe operator asks the AI to gather more evidence
    
            
    rollbackrec_id, minutes_after_applyAn applied fix is undone
    
            
    outcome_verifiedrec_id, metric, before, afterThe monitored metric settles after a fix
    
              
        
    
      
    
    
    
    
    
      
    Patterns on this page
    
      
    
        
    Why, with evidenceEach recommendation shows the signals behind it, against what is typical for that site.
    
        
    Confidence with a track recordThe percentage comes with how often fixes at that confidence were accepted and rolled back.
    
        
    What would change my mindThe AI names the signal that would make it withdraw the recommendation.
    
        
    Preview the changeSetting before and after, who is affected, and how to undo it, before anything runs.
    
        
    Accept, edit or reject with a reasonEdits and reasons are captured as training labels, not lost in a ticket.
    
        
    Risk sets the defaultLow-confidence, high-impact fixes default to investigating first, not applying.
    
        
    The AI can say it does not knowWhen nothing explains the data, it asks for more instead of guessing.
    
        
    Verify, then keep or roll backAfter a fix, the metric is watched and a one-step rollback stays open.
